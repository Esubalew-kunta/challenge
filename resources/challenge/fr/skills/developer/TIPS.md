# Conseils

## Capitaliser sur chaque usage

Après chaque usage, repérez l'instruction qui a donné un bon résultat et celle qui a créé de la confusion. Lorsque la même correction apparaît une deuxième fois, améliorez le skill concerné afin que la prochaine session commence avec un meilleur cadre.

Utilisez cette boucle courte :

1. Lancer le skill sur une vraie tâche.
2. Vérifier le résultat et ses preuves.
3. Noter une erreur répétée ou un contrôle absent.
4. Faire un seul changement à la fois dans le skill.
5. Le relancer sur une tâche similaire.

## Placer la connaissance au bon endroit

- Placez les faits et commandes durables du projet dans `CLAUDE.md`.
- Placez une procédure répétable dans un skill.
- Placez les détails temporaires dans le prompt.
- Placez les explications longues et facultatives dans un fichier de référence lié par le skill.

## Garder des skills solides

- Donnez un seul objectif clair à chaque skill.
- Gardez le fichier principal sous 100 lignes lorsque cela reste possible.
- Faites apparaître les vraies situations de déclenchement dans la description.
- Exigez des preuves pour les affirmations sur le code.
- Gardez les actions risquées derrière une permission explicite.
- Testez un skill avec un exemple simple et un exemple difficile.

N'ajoutez pas toutes les préférences dans tous les skills. Trop de texte peut masquer les règles importantes.
